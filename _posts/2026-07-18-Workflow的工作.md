# “workflow(工作流)”到底咋回事

workflow是将一个任务，拆分成多个步骤，然后使用异步函数，完成一步步的工作，然后最终再组合起来。

为了获得更好的质量，通常需要多个AI配合，需要自己写代码应对每一个环节AI回复里面可能出现的问题，在AI回复的时候，一方面是需要完成这个环节工作的提示词，另一方面，则是需要让AI返回特定的格式内容，以让js或者其他语言能够读取和处理这些回复。

但真正的“工作流”不只是 `await` 排队，它里面藏着好多“防坑”的脏活儿。

## 1. 拆步 + 异步，这是最基础的

比如写论文，你拆成：大纲 → 背景 → 现状 → 原因 → 方案 → 结论。  
代码里就是：

```javascript
let outline = await callAI('写大纲');
let background = await callAI('根据大纲写背景', outline);
let reasons = await callAI('根据背景写原因', background);
// ...
```

这么写能跑，但有个致命问题——任何一个 AI 抽风（返回一堆乱码或者格式不对），整个流程就炸了。所以你得加“保护”。

## 2. 格式锁：逼着 AI 说“人话”

你肯定遇到过，让 AI 返回 Markdown，它返回纯文本，解析不了。怎么办？  
现在主流做法是给 AI 一个 JSON Schema，比如：

```json
{
  "title": "string",
  "sections": [{"heading": "string", "content": "string"}]
}
```

然后代码里用 `response.model_validate()` 强校验，如果校验失败，不报错，而是把“格式错了，重新生成”这句话又塞回给 AI，让它重试。这叫“自我修正”，相当于给 AI 配了个格式纠察员。

## 3. 记忆拼接：别啥都往下一轮塞

每一步都要把前一步的结果传过去。但如果你每一步都全量拼接，Token 烧得飞快。  
我们常用的办法有三种：

- **滑动窗口**：只传最近 2~3 步的摘要，够用。  
- **摘要压缩**：单独开个 AI，把上一步的 5000 字压缩成 200 字的“核心观点”，再传下去。  
- **RAG 检索**：把前面生成的所有内容转成向量，下一步 AI 只“搜”它需要的那一小块，不瞎看。

这就像你开会，不用记每个人说的每个字，只记关键结论就行。

## 4. 多 AI 配合：一个写，一个骂，一个改

为了实现高质量的输出，不得不需要多个 AI 配合，因为不同模型往往擅长的方面不一样，最经典的组合是：

- **执行者**（写初稿）
- **评判者**（专门挑刺：“逻辑不通、字数不够、数据太老”）
- **重写者**（根据批评修改）

代码里就是个 while 循环：

```javascript
let draft = await writeAI(prompt);
let score = await criticAI(draft);
while (score < 6) {
    let comments = await criticAI(draft, '请输出具体缺点');
    draft = await rewriteAI(draft, comments);
    score = await criticAI(draft);
}
```

这就是“反思”机制——AI 自己骂自己，改到满意为止，比你手动改稿子省心多了。

## 5. 异常兜底：哪怕 AI 全崩，系统不能崩

AI 超时、返回空内容、甚至拒绝回答，这些你肯定遇到过。  
工业级工作流里，必须加：

- **重试机制**（最多 3 次，每次等待时间递增）
- **兜底模板**：如果 3 次都失败，直接注入一段预设好的“标准答案”，保证前端永远有内容返回，流程永远不中断。
- **详细日志**：把所有异常记下来，方便你事后复盘是哪里出了问题。

## 6. Hermes 那种“分层记忆”到底怎么实现的？

Hermes 能记更多东西、分层整理、自我分析，其实就是把记忆分成三层：

- **短期**：刚刚聊了啥。
- **长期**：把历史上表现好的框架（比如优秀的大纲、论证结构）向量化存起来。
- **程序性**：记录“什么场景用什么提示词效果最好”。

当你要写“原因分析”时，Hermes 不是傻傻地传上一段结果，而是同时从这三层里检索，把最相关的历史经验也塞进提示词。  
而且它每轮结束后，会调用一个专门的“反思 AI”，给这轮表现打分、列出缺点，然后把这些缺点作为下一轮的“改进指令”。相当于你的 AI 每写一篇，都有一个“毒舌编辑”逼它进步。

## 7. 说穿了，工作流和 Agent 其实是一回事

你手写的工作流，每一步固定，出错就重试，记忆靠拼接。  
而 Hermes 这类高级 Agent，在每一步里嵌入了“动态决策”——自己决定调哪块记忆，自己判断要不要多写一段，自己分析表现并改进。  

所以，**工作流是骨架，Agent 是大脑**。  
workflow的这套“拆步 + 格式约束 + 记忆拼接 + 异常处理”，已经是搭建企业级 AI 应用的核心能力了。只要再往前迈一步，把“异常处理”和“记忆管理”也交给 AI 去动态决策，你就能从“流水线工人”升级成“AI 导演”。
